# ai-log

Веб-приложение для просмотра журналов событий (логов) из PostgreSQL и получения рекомендаций по инцидентам с помощью локальных LLM.

Поддерживаются:
- Провайдеры ИИ: `Ollama`, `LM Studio` (OpenAI-compatible API).
- Два режима ответа: `fast` (быстро) и `reasoning` (более подробно).
- Экспериментальный `RAG v2`: поиск релевантных фрагментов в локальных документах и подмешивание их в промпт.
- Настройки разработчика для тонкой настройки генерации (контекст, потоки CPU, batch, температура и т.д.).
- Система уведомлений внутри UI.

Ниже описано, как устроен проект, как поднять приложение и как его использовать.

---

## 1. Что делает приложение

### 1.1 Основной сценарий
1. Подключаете приложение к PostgreSQL (через форму `/connect`).
2. Выбираете таблицу с логами.
3. На главной странице просматриваете записи, используете поиск/фильтры/сортировку.
4. Открываете конкретный лог, добавляете ручное решение или генерируете решение от ИИ.
5. (Опционально) включаете RAG и загружаете документацию, чтобы ответы ссылались на внутренние документы.

### 1.2 Для каких задач подходит
- Быстрый анализ инцидентов по тексту лога.
- Подсказки по действиям для исправления ошибок (DevOps/SRE контекст).
- Хранение истории решений в БД (таблица `log_solutions`).
- Проверка гипотез / экспериментальная интеграция RAG.

## 3. Структура проекта

Код приложения находится в папке `ai-log/big data/`.

Ключевые файлы:
- `big data/main.py` — создание FastAPI приложения и подключение роутеров.
- `big data/routes_main.py` — главная страница, страница лога, операции с решениями, вызов генерации ИИ.
- `big data/routes_connect.py` — подключение к БД и выбор таблицы с логами.
- `big data/routes_settings.py` — страница настроек, сохранение настроек, управление RAG документами/индексацией.
- `big data/routes_notifications.py` — эндпоинты уведомлений.
- `big data/ai.py` — работа с Ollama/LM Studio (список моделей, генерация fast/reasoning, streaming thinking).
- `big data/rag.py` — экспериментальный RAG v2: чанкинг документов, embeddings, поиск по косинусному сходству.
- `big data/config.py` — загрузка/сохранение локальных JSON конфигов (настройки, фильтры, уведомления).
- `big data/db.py` — подключение к PostgreSQL и создание таблицы `log_solutions`.
- `big data/templates/` — HTML шаблоны (Jinja2).

Тесты (смоук):
- `big data/tests/` — локальные smoke-тесты (в CI часть тестов может быть `skip`).

## 5. Запуск приложения

### 5.1 Запуск локально (только на этом ПК)
Из папки `ai-log/big data`:
```bash
uvicorn main:app --reload
```

По умолчанию будет доступно:
- `http://127.0.0.1:8000/`

### 5.2 Запуск в локальной сети (доступ с телефона/других ПК)
Чтобы открыть приложение с других устройств в вашей подсети, запускайте uvicorn так:
```bash
uvicorn main:app --reload --host 0.0.0.0 --port 8000
```

Открывайте с другого устройства:
- `http://<LAN-IP-ВАШЕГО-ПК>:8000/`

Важно:
- Разрешите входящие подключения в Windows Firewall для порта `8000/TCP`.
- Не используйте `169.254.x.x` (это APIPA/link-local, обычно не маршрутизируется в LAN).

## 6. Подключение к базе данных (PostgreSQL)

### 6.1 Что нужно от БД
- PostgreSQL доступен по сети.
- У вас есть доступ (host/port/dbname/user/password).
- В БД есть таблица с логами (любое имя таблицы в схеме `public`).
- В таблице ожидается наличие поля `id` (используется как идентификатор записи).

### 6.2 Как подключиться
1. Откройте `/connect`.
2. Введите параметры подключения.
3. После успешного подключения выберите таблицу на странице `/tables`.

После выбора таблицы приложение сохранит настройки в `config.json`.

### 6.3 Таблица решений
Приложение создает (если отсутствует) таблицу `log_solutions` для хранения решений:
- ручные решения, введенные пользователем
- решения, сгенерированные ИИ (если вы добавляете их вручную на странице лога)

![Таблица решений](<big data/docs/images/Log_solutions.png>)

## 7. Провайдеры ИИ: Ollama и LM Studio

### 7.1 Выбор провайдера и модели
Откройте `/settings`:
- выберите провайдера (`Ollama` или `LM Studio`)
- выберите модель из списка

Список моделей:
- Ollama: читается через HTTP API (`/api/tags` или `/api/models`)
- LM Studio: читается через HTTP API (`/api/v0/models` или `/v1/models`) и при необходимости через `lms ls --json`

### 7.2 Подключение к удаленному серверу ИИ (в вашей LAN)
Если Ollama/LM Studio запущены на другом устройстве в сети:
- в настройках укажите URL для соответствующего провайдера

Примеры:
- Ollama: `http://192.168.1.10:11434`
- LM Studio: `http://192.168.1.10:1234`

Если поля пустые, используются значения по умолчанию:
- Ollama: `http://localhost:11434`
- LM Studio: `http://localhost:1234`

Важно про `169.254.x.x`:
- Это link-local (APIPA) адрес. Он может отображаться в LM Studio, но обычно плохо работает для доступа из LAN.
- Используйте IP активного интерфейса сервера (Ethernet/Wi‑Fi), обычно `192.168.*.*` или `10.*.*.*`.

## 8. Генерация решения от ИИ: fast vs reasoning

На странице лога есть кнопка генерации решения и переключатель режима:
- `fast`: коротко и максимально быстро
- `reasoning`: более развернуто (с учетом контекста и доп. инструкций)

Как это устроено:
- Приложение собирает текст лога (колонки + значения) в единый `log_text`.
- Формирует промпт в зависимости от режима.
- Вызывает провайдера:
  - Ollama: `/api/generate`
  - LM Studio: `/v1/chat/completions`

## 9. Developer settings (параметры генерации)

На странице `/settings` есть блок "Настройки разработчика".

Параметры могут влиять на:
- производительность
- температуру/энергопотребление
- стабильность (слишком большие значения могут приводить к зависаниям/ошибкам)

Настройки применяются как:
- Ollama: через `options` (например `num_ctx`, `num_thread`, `num_batch`, `temperature`)
- LM Studio: через параметры OpenAI-compatible API (например `temperature`)

## 10. RAG v2 (экспериментально)

RAG нужен для подмешивания релевантных фрагментов документации в запрос к модели.

### 10.1 Как устроен экспериментальный пайплайн
1. Документы (`.txt`/`.md`) складываются в папку `rag_docs/`.
2. Индексация:
   - текст разбивается на чанки
   - для каждого чанка создается embedding через LM Studio `/v1/embeddings`
   - результат сохраняется в `rag_index.json`
3. При генерации решения:
   - лог используется как запрос (query)
   - для query строится embedding
   - выбираются top_k наиболее похожих чанков по косинусному сходству
   - выбранные фрагменты добавляются в промпт

### 10.2 Включение RAG
На странице `/settings`:
- включите галочку `Использовать RAG (экспериментально)`
- выберите embedding модель (скачанную в LM Studio)
- настройте `top_k` и максимальный размер контекста (в символах)

### 10.3 Документы и индексация
В UI можно:
- загрузить документы
- переиндексировать (пересобрать `rag_index.json`)
- удалить документы/очистить индекс (в зависимости от доступных кнопок в UI)

Примечания:
- `rag_index.json` генерируемый файл, его обычно не коммитят в Git.
- Для embeddings обязательно нужен сервер LM Studio с поддержкой `/v1/embeddings` и embedding-модель.

## 11. Уведомления

Уведомления хранятся локально в `notifications.json` и показываются в UI (кнопка 🔔).

Текущий принцип:
- счетчик подтягивается один раз при загрузке страницы
- обновление счетчика выполняется по событиям (без постоянного polling)

## 12. Конфигурационные файлы (локальные)

Приложение хранит часть состояния в JSON рядом с кодом:
- `config.json` — параметры подключения к БД и выбранная таблица
- `settings.json` — выбор провайдера/модели, параметры генерации, URL эндпоинтов
- `filters.json` — пользовательские фильтры
- `notifications.json` — уведомления
- `rag_docs/` и `rag_index.json` — документы и индекс RAG

Для GitHub/CI/CD эти файлы обычно не коммитятся (см. `.gitignore`).

## 14. Troubleshooting

### 14.1 Не открывается с другого устройства в LAN
- Запускайте uvicorn с `--host 0.0.0.0`
- Проверьте firewall (порт `8000/TCP`)
- Используйте LAN IP (`192.168.*.*` или `10.*.*.*`)

### 14.2 LM Studio “reachable at 169.254.*.*” но не работает
- Не используйте `169.254.*.*` для LAN
- Берите IPv4 активного интерфейса (Ethernet/Wi‑Fi), проверьте доступность:
  - `curl http://<IP>:1234/v1/models`

### 14.3 Модели не отображаются
- Проверьте, что запущен Ollama/LM Studio сервер
- Проверьте URL в настройках (если сервер на другом ПК)

### 14.4 RAG не работает / индекс пустой
- Проверьте, что embedding модель выбрана
- Проверьте доступность `LM Studio /v1/embeddings`
- Проверьте, что документы лежат в `rag_docs/` и имеют расширение `.txt`/`.md`
